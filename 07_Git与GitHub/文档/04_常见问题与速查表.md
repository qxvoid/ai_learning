# 04 · 常见问题与速查表

> 这一篇不必通读，是“出事了来翻”的急救手册 + 命令速查表。
> 大部分 Git 报错都不是世界末日。Git 的设计哲学是：**只要你 commit 过，几乎什么都能找回来**。关键是别慌着 `rm -rf`、别乱 force push。

---

## 1. 撤销与回退全家桶（最重要的一节）

新手最常问：“我提交错了 / 想回到上一个版本 / 误删了文件怎么办？” 答案取决于**你想撤回到哪一步、有没有 push 出去**。

### 1.1 先分清：改动发生在哪个区？

| 你的状态 | 想干嘛 | 用什么 |
|---|---|---|
| 文件改了，还没 `add` | 扔掉工作区改动，恢复成上次提交的样子 | `git restore <文件>` |
| 已经 `git add` 了，但没 commit | 把它移出暂存区（改动还在硬盘） | `git restore --staged <文件>` |
| 已经 `commit`，但**还没 push** | 撤销这次提交，回到之前 | `git reset`（见下） |
| 已经 `commit` **并且 push 到 GitHub** | 不想改写公开历史，新加一个“反向提交” | `git revert`（见下） |

### 1.2 git reset 的三档（本机已实测）

```powershell
git reset --soft HEAD~1     # 只把 HEAD 指针退一格，改动留在暂存区
git reset --mixed HEAD~1    #（默认）退一格，改动留在工作区，取消暂存
git reset --hard HEAD~1     # 退一格，改动直接丢弃（危险！）
```

实测场景：我误提交了一个 `bad.py`：

```powershell
git reset --soft HEAD~1     # 撤销提交，但 bad.py 还在暂存区（状态 A）
# 我确认这就是我要的效果，文件没丢，只是那次 commit 没了
```

| 档位 | 暂存区 | 工作区 | 何时用 |
|---|---|---|---|
| `--soft` | 保留（改动仍 staged） | 保留 | 想改完说明重新 commit |
| `--mixed`（默认） | 取消暂存 | 保留 | 想重新挑选 add 哪些 |
| `--hard` | 清空 | **丢弃所有未提交改动** | 确定不要了，回到干净的上个版本 |

> **`--hard` 会物理丢弃未提交的改动，不可恢复。** 用之前先 `git status` 看清楚。

### 1.3 git revert：对已 push 的提交做“反向操作”

一旦你 push 到 GitHub，**不要用 reset 去改写公开历史**（会和别人的历史冲突）。正确做法是 `revert`：它新建一个提交，内容是“把那次提交的改动反过来”。

本机实测：先提交 `feat: v3`，再撤销它：

```powershell
git revert --no-edit HEAD
```

历史里多出一条 `Revert "feat: v3"`，原提交还在，只是效果被抵消了。这样公开历史是只增不改的，协作安全。

### 1.4 git reflog：后悔药的总登记簿

哪怕你 `reset --hard` 把提交搞没了，HEAD 移动过的每一步 Git 都记着。本机实测 `git reflog -8`：

```
efb35aa HEAD@{0}: revert: Revert "feat: v3"
e499844 HEAD@{1}: commit: feat: v3
a048cb8 HEAD@{2}: reset: moving to HEAD
b5c718e HEAD@{4}: commit: wip: bad commit
```

看到 `b5c718e`（那个你以为丢了的坏提交）还在！想找回它：

```powershell
git reflog                      # 找到你想要的那条哈希，比如 b5c718e
git reset --hard b5c718e        # 把 HEAD 指回去，文件就回来了
```

> **reflog 只存在你本地**，约 90 天后自动清理。但它是你本地“手滑”时的终极救命稻草。

## 2. 误删文件 / 误删提交，怎么救

- **误删了工作区文件，但它以前 commit 过**：
  ```powershell
  git restore 被删的文件.py       # 从版本库恢复
  ```
- **误删了整个提交（reset 过头）**：用上面 1.4 的 `git reflog` 找回哈希再 `reset --hard`。
- **commit 到一半发现漏了个文件**：
  ```powershell
  git add 漏掉的文件
  git commit --amend --no-edit   # 把这次改动塞进上一次提交，不改说明
  ```
  （`--amend` 会改写最后一次提交，**没 push 过才安全**。）

## 3. CRLF 换行符问题

**症状**：你明明只改了一行，`git diff` 却显示整个文件每一行都变了；或者提交时一堆 `LF will be replaced by CRLF` 警告。

**原因**：Windows 换行是 `\r\n`（CRLF），Mac/Linux 是 `\n`（LF）。

**解决**（本机当前 `core.autocrlf` 为空，建议设上）：

```powershell
git config --global core.autocrlf true
```

含义：仓库里统一存 LF，Windows 检出时转成 CRLF。设完再提交就不会整文件飘红了。

## 4. 中文乱码

### 4.1 中文文件名显示成 `\351\234...`

```powershell
git config --global core.quotepath false
```

### 4.2 commit 说明中文变乱码

PowerShell 5.1 默认编码有时不是 UTF-8。确保：

```powershell
git config --global core.quotepath false
```

写中文提交说明时尽量用 `-m "中文说明"` 单行，一般没问题。若用编辑器写，把编辑器编码设为 UTF-8。

## 5. 认证失败（Authentication failed）

**症状**：`git push` 弹框或命令行要密码，输了还是 `Authentication failed`。

**最常见原因**：你在“密码”那一栏输入了 GitHub 登录密码。GitHub 早就不接受它了，必须用 **PAT**（见 02 文档 2.1）。

**解决**：

1. 重新去 GitHub 建一个 PAT（Developer settings → Personal access tokens），勾 `repo` 权限。
2. 清掉 Windows 里存错的旧凭证：
   ```powershell
   git config --global --unset credential.helper   # 先看是不是它在捣乱
   ```
   然后打开 Windows 的“凭据管理器”（控制面板 → 凭据管理器 → Windows 凭据），找到 `git:https://github.com`，删掉它。
3. 下次 `git push` 重新弹窗，用户名填 GitHub 用户名，密码**粘贴 PAT**。

## 6. 大文件

**症状**：`remote: error: File xxx.csv is 150.00 MB; this exceeds GitHub's file size limit of 100.00 MB`。

**原则**：Git 不适合存大数据集、二进制模型文件。你的做法应该是：

1. **根本别让它进 Git**：在 `.gitignore` 里写 `*.csv`、`data/`、`*.zip`、`*.pkl`、`*.parquet`。
2. 如果已经 commit 进去了，光删文件不够（它还在历史里），要用 `git rm --cached` + 重写历史（见下）。
3. 真的必须传大文件（比如模型），用 **Git LFS**：
   ```powershell
   git lfs install
   git lfs track "*.pkl"
   git add .gitattributes
   ```

**从历史里彻底移除一个误入的大文件**（谨慎，会改写历史，没 push 给别人时再用）：

```powershell
git rm --cached 大文件.zip
# 若它已经在历史中，需要 git filter-repo 或 BFG，属于进阶，本模块不展开
```

> 对学生 EDA 项目：数据集别传，README 里写一句“数据来自 MovieLens，自行下载放入 data/”即可。

## 7. 忽略一个已经被跟踪的文件

**症状**：你把 `config.local.py` 写进了 `.gitignore`，但 Git 还是一直跟踪它。

**原因**：`.gitignore` 只对未跟踪文件生效。它之前已经被 `git add` 过了。

**解决**（本机实测）：

```powershell
git rm --cached config.local.py     # 从跟踪中移除，但硬盘文件保留
git commit -m "chore: stop tracking local config"
```

之后它就被 `.gitignore` 管住了。

## 8. 命令速查表（贴墙版）

### 8.1 本地日常

| 目的 | 命令 |
|---|---|
| 初始化仓库 | `git init` |
| 看状态 | `git status` |
| 看改动（工作区） | `git diff` |
| 看暂存改动 | `git diff --cached` |
| 暂存全部 | `git add .` |
| 暂存指定文件 | `git add 文件` |
| 提交 | `git commit -m "说明"` |
| 把改动塞进上次提交 | `git commit --amend --no-edit` |
| 历史 | `git log --oneline --graph --all` |
| 看某条提交详情 | `git show 哈希` |
| 丢弃工作区改动 | `git restore 文件` |
| 取消暂存 | `git restore --staged 文件` |
| 临时藏起当前改动 | `git stash push -m "说明"`（未跟踪文件加 `-u`） |
| 取出最近一次 stash | `git stash pop` |

### 8.2 远程

| 目的 | 命令 |
|---|---|
| 关联远程 | `git remote add origin URL` |
| 查看远程 | `git remote -v` |
| 首次推送并绑定 | `git push -u origin main` |
| 以后推送 | `git push` |
| 拉取（下载+合并） | `git pull` |
| 只下载不合并 | `git fetch` |
| 克隆 | `git clone URL` |
| 同步 fork 的上游 | `git fetch upstream && git merge upstream/main` |

### 8.3 分支与标签

| 目的 | 命令 |
|---|---|
| 列分支 | `git branch` |
| 新建并切换 | `git switch -c 分支名` |
| 切换 | `git switch 分支名` |
| 合并 | `git merge 分支名` |
| 中止合并 | `git merge --abort` |
| 删分支 | `git branch -d 分支名` |
| 打附注标签 | `git tag -a v1.0 -m "说明"` |
| 推送标签 | `git push origin v1.0` |

### 8.4 后悔药

| 目的 | 命令 |
|---|---|
| 撤销最近一次提交，保留改动 | `git reset --soft HEAD~1` |
| 撤销最近一次提交，改动退回工作区 | `git reset HEAD~1` |
| 硬回退，丢弃改动 | `git reset --hard HEAD~1` |
| 反向撤销已 push 的提交 | `git revert 哈希` |
| 查看 HEAD 所有移动记录 | `git reflog` |

## 9. VSCode 内置 Git 用法

你已经装了 VSCode（`code --version` 可用）。它内置了完整 Git 图形界面，**对新手比敲命令更友好**：

1. **左侧第三个图标（分支形）**就是“源代码管理”（Ctrl+Shift+G）。
2. 改完文件，这里会列出所有改动；点 `+` 就是 `git add`，在顶部消息框写说明，打勾就是 `git commit`。
3. 文件名旁边的数字是改动行数；点开能看到**逐行 diff**（绿色是新增，红色是删除），比命令行直观。
4. **分支**：左下角点当前分支名（如 `main`），会弹出菜单让你新建/切换分支。
5. **推送/拉取**：底部状态栏有 `⇡` `⇣` 箭头，点一下就是 push / pull。
6. **解决冲突**：合并冲突时，VSCode 会在冲突代码上方弹出“接受当前更改 / 接受传入更改 / 两者都接受”的按钮，点一下就解决，不用手动删尖括号。
7. **历史**：装个扩展（如 GitLens）能看到每一行是谁、哪次提交改的，读源码时极有用。

> 建议：本地日常用 VSCode 点，理解原理时回到命令行。两边是同一套东西，图形只是壳。
